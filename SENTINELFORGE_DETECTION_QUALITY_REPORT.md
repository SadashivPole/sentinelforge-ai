## 1. Executive Summary

An independently authored holdout dataset (69 events, NOT generated by sentinelforge.datasets.scenarios) was used to evaluate detection quality. Results show perfect precision and recall for 4 of 5 rules. C2BeaconRule achieves 100% recall but 54.55% precision, flagging legitimate periodic HTTPS traffic as false positives. Overall: Precision=0.8182, Recall=1.0000, F1=0.9000.

## 4. Key Findings

### 4.1 C2BeaconRule False Positives (Primary Limitation)

C2BeaconRule flagged 10 legitimate periodic HTTPS connections to `40.70.12.100:443` (known software update server, 30-minute intervals) as beaconing. These events have:
- Destination port 443 (standard HTTPS)
- Known update server IP
- 30-minute intervals (not rapid beaconing)

**Analyst guidance:** Distinguish beaconing from legitimate periodic traffic by:
- Destination reputation (known update server vs. unknown IP)
- Port (443 vs. non-standard ports like 8443)
- Interval (30+ minutes vs. sub-minute to 5-minute beaconing)

### 4.2 No False Negatives

All 45 suspicious ground-truth events were detected (recall = 1.0000). No malicious activity was missed.

### 4.3 Benign PowerShell Not Flagged

All 3 benign PowerShell events (RemoteSigned, NoProfile, Get-Help) were correctly NOT flagged by SuspiciousPowerShellRule. Only execution_policy_bypass + encoded_command combinations trigger.

### 4.4 Single-User Failures Not Flagged as Spraying

5 authentication failures against a single account were correctly NOT flagged by PasswordSprayRule (requires 3+ distinct usernames).
