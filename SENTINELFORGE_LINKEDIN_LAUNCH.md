## 1. Launch Post (Full Version)

### Headline

I'm sharing SentinelForge AI, a prototype detection pipeline for SOC log analysis — built to demonstrate how raw security logs flow from ingestion to analyst-ready alerts, with full evidence traceability.

### Body

After months of building detection pipelines, I wanted to create something that shows the complete picture — not just individual rules in isolation, but the full flow from raw log to analyst-ready alert.

SentinelForge AI is a Python-based prototype that demonstrates:

- **Log ingestion:** JSON, JSONL, and Sysmon EVTX-converted JSON readers with no silent data loss
- **Normalization:** Common event schema with raw evidence preserved verbatim
- **Detection:** 5 rules (failed login burst, password spray, suspicious PowerShell, suspicious process tree, C2 beaconing), each citing exact raw log evidence
- **Risk scoring:** Deterministic 0-100 score per host with 5 weighted factors
- **Storage:** SQLite with foreign-key enforcement and immutability checks
- **Evaluation:** Independent alert-level precision and event-level recall models against independently authored holdout data

### What the validation shows

- 208/208 pytest tests passing
- Holdout detection: Precision 0.82, Recall 1.00, F1 0.90
- SQLite integrity and foreign-key checks pass
- SHA-256 reproducible dataset generation (seed=42)

### What it's NOT

- Not a production SIEM
- Not real-time streaming (batch-only architecture)
- No AI investigation agent (mock provider only)
- No authentication/authorization
- No encryption at rest

This is a learning and demonstration tool — for SOC analysts, detection engineers, and anyone who wants to understand how a detection pipeline works end to end.

Open sourcing soon (pending approval). MIT license.

## 3. Technical Follow-Up Post

### Headline

Deep dive: How SentinelForge AI evaluates detection quality without inflated metrics

### Body

Most detection projects report inflated accuracy because they test on the same data they trained on. SentinelForge AI takes a different approach.

We use an **independently authored holdout dataset** (69 events, NOT generated by the scenario code) to evaluate detection quality:

- 45 suspicious events, 24 benign
- 45 true positives, 10 false positives, 0 false negatives
- Precision: 0.82, Recall: 1.00, F1: 0.90
- Alert-level precision and event-level recall are independent models — no F1 cross-contamination
- Attribution errors tracked separately from false positives

The 10 false positives all come from C2BeaconRule flagging legitimate periodic HTTPS traffic — a known limitation we're documenting, not hiding.

Metrics should be honest, not impressive. #DetectionEngineering #SOC #Cybersecurity #Metrics
