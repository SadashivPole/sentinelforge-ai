Architecture

Three separated experiences share a common Python detection core.

Three separated experiences

  • Public website: Static HTML/CSS/JS hosted on GitHub Pages. No Python, no database.
  • Interactive demo: Browser-side JavaScript rendering precomputed synthetic results only.
  • Local SOC dashboard: Python HTTP server on 127.0.0.1:8080 backed by local SQLite.

Common detection core

The sentinelforge/ Python package powers both the CLI (sentinelforge ingest, sentinelforge detect) and the local dashboard. All detection logic runs in Python — there is no JavaScript detection engine.

Data flow

Raw logs are ingested and normalized locally. Detection results are stored in SQLite. The public website displays only sanitized, precomputed JSON exports — never live data.

Public vs local boundary

  • Public: Website and interactive demo hosted on GitHub Pages. Static files only — no Python, no database.
  • Local: Python SOC dashboard binds to 127.0.0.1:8080 only, backed by a local SQLite file. Never exposed publicly.
  • Shared: The common Python detection engine (sentinelforge/) powers both the CLI and the local dashboard.
  • No JavaScript detection engine: All detection runs in Python. The browser only renders exported, precomputed results.
