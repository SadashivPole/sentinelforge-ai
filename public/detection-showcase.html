Detection engineering showcase

Real results from the SentinelForge Python detection engine, exported from a synthetic dataset and presented as static, precomputed output. No live detection runs in the browser.

How this was generated

  1. Generated 22 synthetic security events using the SentinelForge dataset generator.
  2. Ingested and normalized the events through the real Python CLI (sentinelforge ingest).
  3. Ran the Python detection engine (sentinelforge detect) producing 5 alerts.
  4. Exported sanitized detection results to static JSON for public display.
  5. The browser renders only the exported JSON — no detection logic runs client-side.

Known limitation — C2 beaconing vs benign traffic

All 18 false positives originated from C2BeaconRule flagging benign periodic HTTPS traffic (software updates, EDR heartbeats, monitoring telemetry). C2BeaconRule cannot reliably distinguish benign periodic traffic from low-frequency C2 beaconing because both produce regular periodic connections. Available telemetry (interval, port, protocol, process, destination IP) cannot reliably distinguish them. All other detection rules produced zero false positives. Analyst investigation with destination reputation and process context is required.
